* How does this work?

I write all of my documentation and blog posts in Org mode, from within Emacs, and I also use Emacs to generate the HTML from those files, which I then host online.

This repository is an Emacs Lisp tool that builds and publishes [[https://jointhefreeworld.org][jointhefreeworld.org]] using Org-mode publishing. It relies on a custom HTML export backend to turn Org files into a fully styled static site, with a few dynamic touches on the home page.

- *Custom HTML export* :: A derived ~site-html~ backend generates every page with a shared header, footer, and layout.
- *Multi-project publishing* :: Content is organized into several projects (home, blog, documentation, platform, portfolio) through ~org-publish-project-alist~.
- *RSS feed generation* :: The ~webfeeder~ package builds an RSS feed from the published blog articles.
- *Extras* :: A tiny dependency-free script (~static/js/freeworld.js~) adds an interactive acronym, a browser-side Lisp REPL, and an easter egg to the home page.

* Using

You will need:

- *Emacs 29.1 or newer*
- *Git* (for version control and for the build hash shown in the footer)

The script at ~./jointhefreeworld-site.el~ sets up a local ~.packages~ directory and installs the packages it needs from MELPA and MELPA Stable: ~esxml~, ~htmlize~, ~webfeeder~, and the language major modes (~haskell-mode~, ~rust-mode~, ~kotlin-mode~) used to fontify code blocks.

Publish the entire site with:

#+begin_src sh
  emacs -Q --batch -l ./jointhefreeworld-site.el --funcall jfw/publish
#+end_src

* Development

The build is driven by [[https://codeberg.org/jjba23/maak][Maak]], a Make-like task runner written in Guile Scheme. Install GNU Guix and Maak, then use the tasks defined in ~maak.scm~:

#+begin_src sh
  maak dev               # hot-reloading dev server (watchexec + darkhttpd)
  maak build             # one-off production build of ./public
  maak build-and-serve   # build, then serve ./public on port 50011
  maak fmt               # format Scheme and Emacs Lisp sources
  maak lint-css          # run stylelint over the stylesheet
  maak deploy            # build for CI and copy ./public to the deploy dir
#+end_src

The ~dev~ (alias ~hr~) task watches Org, Emacs Lisp, Scheme, and CSS files, and rebuilds the site whenever one of them changes.

* Configuration

The ~org-publish-project-alist~ variable defines the published projects (home, blog, documentation, platform, portfolio). Adjust those entries to match your own directory layout.

Customize the look and feel by editing functions such as ~jfw/site-header~, ~jfw/site-footer~, and ~jfw/generate-page~.

* On reproducibility: why GNU Guix?

A build should never fail because "it worked on my machine". Reliable software development demands explicit, bit-for-bit reproducibility and a functional approach to package management and system deployment.

#+BEGIN_EXPORT html
<a href="https://guix.gnu.org/">
  <img src="https://jointhefreeworld.org/ggg/dist/gnu-guix.svg" alt="GNU Guix logo" style="max-width: 250px; width: 100%; height: auto;" />
</a>
#+END_EXPORT

- *Declarative build graphs* :: Packages are pure functions of their inputs, with no implicit system state.
- *Programmable with Guile* :: Full system and package configurations written in [[https://www.gnu.org/software/guile/][Guile Scheme]], rather than rigid DSLs or static files.
- *Time travel* :: Rebuild the exact system state from any point in Git history using ~guix time-machine~.
- *Atomic operations* :: Upgrade or roll back environments instantly, without leaving orphaned dependencies or broken states.
- *Unified tooling* :: A single tool manages development shells, isolated containers, package builds, and full system configurations.
